# 1.3.4 TTS 与重复排版验证（2026-10-28）

## 范围与环境

Android 15/API 35 ARM64 模拟器，1080×2400、3 GB、2 核、软件图形。使用自行生成的三章中英文 EPUB；不使用私人书籍正文。生产代码保留 `kDebugMode` 控制 WebView 调试；性能 APK 临时启用调试，仅作为本地验证产物，不用于发布。

## 语速控件

语速范围 0.1～4.0，每次 0.1，支持手动输入；非法值不改变已保存语速，提交与失焦不会重复更新朗读服务。默认可见边框高 28 dp，触控高 48 dp；按后续反馈缩为居中短控件，数值区域 42 dp，默认控件总宽 140 dp。音调与语速各占一半；窄屏时名称居中位于对应控件上方，宽屏时名称与控件同行。音调 0.5～2.0，每次 0.1，也支持输入。极大无障碍文字可横向滚动，不压缩字体或触控目标。

模拟器已验证输入 4.0、0.1、拒绝 4.1，恢复原 0.6。高度截图来自缩短前的 28 dp 版本；最终宽度由组件测试验证，用户随后取消截图打包。组件测试覆盖全部 39 次加速、边界禁用、输入和按钮混用、错误纠正及大字窄屏。

## 小米 MiMo 音调

安卓将音调传至现有 MediaPlayer PlaybackParams，合成及缓存键使用中性音调，避免重复合成和双重调音。其他平台保留服务端风格指令，按不同档位发送具体数值；不承诺服务精确执行倍率。

使用真实 Android 播放器及本地生成的 440 Hz WAV，通过 OnlineTts 的 MiMo 分支依次执行 0.5、0.8、1.1、1.6、2.0 音调，再执行 1.7 语速与 1.3 音调、暂停时改 0.7、继续。结束时 error=null，生成请求始终为 1；原生媒体服务确认暂停、继续及 speed=1.7。自动测试另外覆盖切段、缓存保留、非法音调及暂停不自动播放。

没有调用付费 MiMo 接口，没有采集用户音频；未测量输出音频频谱，也未进行真实小米设备听感验收。原生 dumpsys 未提供 pitch 数值，不能把无异常日志称为音高倍率测量。

## 排版对比

同一测试书第 2 章、同一阅读位置和样式；每个版本独立运行五轮，操作后等待 12 个动画帧。下面为各轮操作耗时中位数，包含原有翻页动画；不包含 UIAutomator/截图耗时。使用旧、新 APK 在同一模拟器做前后对比，不与并行测试抢占 CPU。

| 操作 | 修改前 ms | 修改后 ms |
|---|---:|---:|
| 相同字号重复设置 | 0.8 | 0.5 |
| 下一页 | 363.4 | 355.7 |
| 上一页 | 302.8 | 303.9 |
| 字号 1.4→1.5 | 458.9 | 463.6 |
| 字号恢复 1.4 | 445.8 | 441.8 |
| 上边距增加 | 328.7 | 299.4 |
| 上边距恢复 | 323.8 | 299.1 |

字号重排的 Range.getClientRects 调用 8255→154，上边距调整 8253→152，约减少 98.1%；这是接口调用次数，不是所有布局工作量。合并 Range 仍检查所有返回字形矩形，不按单个字符猜测字体高度。字号重排的位置刷新 5→4，边距重排 3→2；普通翻页仍刷新一次。

本样本边距调整耗时减少约 7.6%～8.9%，字号调整总耗时基本不变。所有对应操作的 CFI、章节和页数一致。未连接真实电子墨水设备，不能推断硬件刷新、残影或整机提速幅度。连续阅读相同样式跳过重复 render 的结果见同日 Android 阅读流程记录；鸿蒙节流验证见同日同步与滚动记录。

原始数据和本地测试产物位于 `output/android-reader-verification/`：`perf-before-repeat.json`、`perf-after-repeat.json`、`pitch-native-logcat.txt`、`pitch-native-player.txt`。这些调试 APK 不作为正式版发布。

## 发布回归

本地完整 Flutter 回归通过 3443 项、跳过 13 项，8 项失败均来自原版文档面板的测试替身未实现新增强制 OCR 属性。补齐替身后，全部受影响文档面板、最终音调／语速控件及 MiMo 原生方法桥接的 29 项测试通过；新增控件测试覆盖宽窄两列、大字及两者设置互不覆盖。

Python 213 项（16 跳过）通过；阅读器 JavaScript 首轮 795 项通过，旧 WebView 引导脚本测试因临时目录缺少 CI 已固定的 acorn 未执行，补齐后其 9 项通过。原生工作线程和 QQ 组件检查通过，未在本地发送通知。依赖、本地化及代码生成成功。原生跨平台安装包和完整云端回归以发布门禁结果为准。

## 第二轮内存与滚动检查

裁边检测将积分图改为足够容纳 2 MP 灰度总和的 Uint32Array，并在各阶段完成后复用灰度数组及积分图空间。1024×1536 合成扫描页五轮对照中，临时工作缓冲区由 22,041,608 字节降至 7,875,588 字节，减少 64.3%，裁边结果完全一致，原图像素保持不变。这是工作缓冲区分配量，不是整个应用内存降幅；本轮不据此宣称裁边速度提升。

TTS 缓存和播放段共用不可写的 Uint8List 视图，避免再次复制完整音频。1 MiB 样本验证缓存命中时不增加合成请求、视图不允许修改且可通过原生平台消息编解码。PDF 串行队列不再持有完成结果；独立 Node GC 实验中，清空缓存后旧版本仍引用 4 MiB Blob，新版本可回收它。

同一 PDF 区域的并发请求仅渲染一次；区域、尺寸及增强设置未变时复用现有清晰图层和 URL。失败不更新复用标记，下次可重试。另修复 2 MP 以上滚动底图不能增强的问题：增强支持原有 8 MP 底图上限，裁边分析仍保持 2 MP 限制。

滚动行测量复用相邻文字片段的 Range，按行合并矩形后再排序，减少临时对象。两段共 100 个生成文字片段的测试中，测量次数由 100 次降至 2 次，行边界一致；未变化时不重测，失效后正确重测。

本轮阅读器广泛回归最初 781 项通过，安卓滚动补充后最终 783 项通过；最终四组受影响 JavaScript 测试 104 项通过。TTS 与控件回归 237 项通过、1 项跳过，修改的 Dart 文件静态分析无问题。

同一安卓模拟器五轮模式切换对照中，进入滚动模式的 Range 矩形测量中位数由 25,056 降至 756，减少 97.0%；25 对操作的 CFI 与页数均一致。相同模式重复设置均为零次重排；滚动下一页／上一页均未触发 render，精确位置各更新一次。切换滚动模式的同步 render 总耗时中位数为 449.8→440.7 ms，操作同步调用为 234.9→238.5 ms；含动画的滚动前后翻页为 259.1→267.7 ms、266.7→280.3 ms，不据此宣称总响应速度提升。

实际 ADB 左右滑动各翻一页、各刷新一次位置，没有重排或重新加载章节。连续模式的上下滑动也没有重排或重新加载；第 2、3 章来回跳转四次均复用原 Document，新增 load 调用为零。这些是模拟器运行证据，不代表真实墨水屏硬件效果。

进一步将鸿蒙已有的 100 ms 精确位置合并用于安卓：120 Hz 单秒滚动回归从 120 次文字扫描降至 11 次；章节点亮与预加载仍逐帧跟进，scrollend、导航和翻页立即提交最终位置，页面替换与关闭可取消延迟任务。Apple、桌面及安卓／鸿蒙分页模式保持原有更新频率。新增测试先复现 120≠11 的失败，修改后相关 47 项通过。

最终重新构建并安装安卓包后，左右滑动仍各翻一页、各更新一次位置。相同上下拖动的精确位置刷新由 8／10 次降至 7／7 次，Range 边界测量由 90／72 次降至 62／62 次，结束 CFI 一致；未触发重排或新增章节加载。连续模式来回切章仍复用同一 Document。原始数据另存于 `memory-audit/gestures-after.json` 和 `memory-audit/gestures-final.json`，五轮滚动模式对照在 `memory-audit/scroll-before.json`、`scroll-after.json`。
